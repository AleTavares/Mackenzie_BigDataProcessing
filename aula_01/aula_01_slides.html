🐼 Por Que Pandas Não Escala?

  1. Memória limitada — Todo o DataFrame cabe na RAM
    Regra: precisa de 5-10x a RAM do tamanho dos dados
  2. Single-threaded — Usa apenas 1 core da CPU
  3. Sem paralelismo — Não distribui entre máquinas
  4. Sem lazy evaluation — Cada operação executa imediatamente
# Isso tenta carregar TUDO na memória:
df = pd.read_csv("vendas_100M.csv")  # 💀 MemoryError

⚡ O Que É Apache Spark?

Motor de processamento distribuído de dados, projetado para ser rápido, generalista e tolerante a falhas.
  • 🚀 In-memory: até 100x mais rápido que Hadoop MapReduce
  • 🐍 APIs: Python (PySpark), Scala, Java, R
  • 📦 Unificado: batch, streaming, ML, grafos
  • 🔄 Lazy evaluation: otimiza antes de executar
  • 💪 Fault-tolerant: recupera de falhas automaticamente
  • 🌐 Open source: Apache Foundation (desde 2009, UC Berkeley)

🏗️ Papel de Cada Componente

ComponenteFunçãoAnalogia
DriverCoordena: cria DAG, distribui tasksMaestro
Cluster ManagerGerencia recursos (CPU, RAM)RH
ExecutorsExecutam tasks em paralelo + cacheMúsicos

Fluxo:

  1. Driver cria plano de execução (DAG)
  2. Solicita recursos ao Cluster Manager
  3. Cluster Manager aloca Executors
  4. Driver distribui tasks → Executors processam em paralelo
  5. Resultados consolidados no Driver

Lazy Evaluation

O segredo da performance do Spark

MACKENZIE

😴 Lazy Evaluation

O Spark não executa operações imediatamente. Constrói um plano (DAG) e só executa quando uma ação é chamada.
# Nenhuma dessas linhas executa nada:
df = spark.read.csv("vendas.csv")             # transformação
df_sp = df.filter(col("state") == "SP")       # transformação
df_total = df_sp.groupBy("city").sum("amount")# transformação

# Só AQUI executa tudo (otimizado):
df_total.show()  # ← AÇÃO!

Benefícios:

  • Otimização global do plano inteiro
  • Elimina operações desnecessárias
  • Minimiza leitura de disco e rede
MACKENZIE

🔀 DAG — Directed Acyclic Graph

┌──────────┐    ┌──────────┐    ┌──────────┐    ┌──────────┐
│ read CSV │───►│  filter  │───►│ groupBy  │───►│  show()  │
│(transf.) │    │(transf.) │    │(transf.) │    │  (AÇÃO)  │
└──────────┘    └──────────┘    └──────────┘    └──────────┘
                                                      │
                                                      ▼
                                                 EXECUTA TUDO

Conceitos-chave:

  • Job: disparado por uma ação
  • Stage: grupo de transformações sem shuffle
  • Shuffle: redistribuição de dados (operação cara!)
  • Task: unidade mínima — 1 task = 1 partição
MACKENZIE

⚙️ Transformações vs Ações

Transformações (Lazy)

  • Constroem o DAG
  • Retornam novo DataFrame
  • Não executam nada

select() · filter() · groupBy() · join() · withColumn() · orderBy()

Ações (Eager)

  • Disparam a execução
  • Retornam valores ao Driver
  • Executam o DAG inteiro

show() · count() · collect() · write · first()

🧠 Catalyst Optimizer

Unresolved ──► Logical ──► Optimized ──► Physical
  Plan           Plan       Plan           Plan
 (parsing)    (análise)  (otimização)   (execução)

Otimizações automáticas:

  1. Predicate Pushdown: filtra antes de ler
  2. Column Pruning: lê apenas colunas usadas
  3. Constant Folding: resolve constantes em compile-time
  4. Join Reordering: reordena para minimizar shuffle
# Você escreve:
df.select("name", "city").filter(col("state") == "SP")

# Spark otimiza para:
# 1. Lê APENAS colunas name, city, state
# 2. Filtra DURANTE a leitura (pushdown)
# 3. Retorna apenas name e city
