🔗 Joins — Combinando DataFrames

Um join combina registros de dois DataFrames baseado em uma condição de igualdade entre colunas.
df_resultado = df_vendas.join(
    df_clientes,                    # DataFrame direito
    df_vendas.customer_id == df_clientes.customer_id,  # Condição
    "inner"                         # Tipo de join
)

# Sintaxe simplificada (coluna com mesmo nome):
df_resultado = df_vendas.join(df_clientes, "customer_id", "inner")

📡 Broadcast Join — Tabela Pequena

Quando uma das tabelas é pequena (< 10MB), o Spark pode broadcast (enviar cópia completa) para todos os executors, evitando shuffle.
                 ┌──────────────┐
                 │ df_categorias│ ← Tabela pequena (200 registros)
                 │   (broadcast)│
                 └──────┬───────┘
            cópia completa enviada a todos
          ┌─────────────┼─────────────┐
          ▼             ▼             ▼
┌─────────────┐  ┌─────────────┐  ┌─────────────┐
│Executor 1   │  │Executor 2   │  │Executor 3   │
│Vendas P.1   │  │Vendas P.2   │  │Vendas P.3   │
│+ categorias │  │+ categorias │  │+ categorias │
│(join local) │  │(join local) │  │(join local) │
└─────────────┘  └─────────────┘  └─────────────┘
      SEM SHUFFLE! Join 100% local em cada executor

from pyspark.sql.functions import broadcast

# Forçar broadcast da tabela de categorias
df_enriquecido = df_vendas.join(
    broadcast(df_categorias), "category_id", "left"
)

📈 Totais e Médias Acumuladas

from pyspark.sql.functions import sum as spark_sum, avg as spark_avg
from pyspark.sql import Window

# Do início da partição até a linha atual
window_acumulado = Window.partitionBy("customer_id") \
    .orderBy("order_date") \
    .rowsBetween(Window.unboundedPreceding, Window.currentRow)

df_acumulado = df_vendas.withColumn(
    "total_acumulado", spark_sum("total_amount").over(window_acumulado)
)

# Média móvel dos últimos 3 pedidos
window_movel = Window.partitionBy("customer_id") \
    .orderBy("order_date") \
    .rowsBetween(-2, Window.currentRow)

df_media_movel = df_vendas.withColumn(
    "media_movel_3", spark_avg("total_amount").over(window_movel)
)
FrameSignificado
rowsBetween(unboundedPreceding, currentRow)Do início ao registro atual
rowsBetween(-2, currentRow)2 anteriores + atual
rowsBetween(-1, 1)Anterior + atual + próximo
rangeBetween(unboundedPreceding, currentRow)Baseado em valor (não posição)

UDFs

User Defined Functions — Funções personalizadas

MACKENZIE

🧩 UDFs — Funções Personalizadas

Uma UDF permite aplicar lógica Python customizada a cada registro de um DataFrame Spark.
from pyspark.sql.functions import udf
from pyspark.sql.types import StringType

@udf(returnType=StringType())
def classificar_ticket(valor):
    """Classifica o ticket do pedido em faixas."""
    if valor is None:
        return "indefinido"
    elif valor < 50:
        return "baixo"
    elif valor < 200:
        return "medio"
    elif valor < 500:
        return "alto"
    else:
        return "premium"

# Aplicar a UDF
df_classificado = df_vendas.withColumn(
    "faixa_ticket", classificar_ticket(col("total_amount"))
)

Quando usar: Lógica de negócio complexa que NÃO pode ser expressa com funções built-in do Spark.

MACKENZIE

⚠️ UDFs — O Custo Escondido

┌─────────────────────────────────────────────────────────────────┐
│  FUNÇÕES BUILT-IN (col("x") + 1)                               │
│  JVM ──── executa nativamente ──── resultado                    │
│  Zero overhead. Otimizado pelo Tungsten.                         │
└─────────────────────────────────────────────────────────────────┘

┌─────────────────────────────────────────────────────────────────┐
│  UDF Python (@udf def minha_funcao(x): ...)                     │
│  JVM → serializa → Python → executa → serializa → JVM          │
│  Para CADA REGISTRO! (1M registros = 1M serializações)          │
└─────────────────────────────────────────────────────────────────┘
OperaçãoTempo (1M registros)Relativo
Built-in when/otherwise0.8s1x (baseline)
UDF Python simples12s15x mais lento
UDF com import externo25s31x mais lento
Pandas UDF (vectorized)2.5s3x mais lento
Regras de ouro: 1) Primeiro tente built-in · 2) Se precisar UDF, use Pandas UDF · 3) UDF Python comum é último recurso

🐼 Pandas UDF — Melhor dos Dois Mundos

Pandas UDF (Vectorized UDF) processa dados em batches usando Apache Arrow, evitando serialização registro-a-registro.
import pandas as pd
from pyspark.sql.functions import pandas_udf
from pyspark.sql.types import StringType

@pandas_udf(StringType())
def classificar_ticket_pandas(valores: pd.Series) -> pd.Series:
    """Versão vetorizada — 5-10x mais rápida que UDF comum."""
    return valores.apply(
        lambda v: "indefinido" if v is None
        else "baixo" if v < 50
        else "medio" if v < 200
        else "alto" if v < 500
        else "premium"
    )

# Uso idêntico ao UDF normal
df_classificado = df_vendas.withColumn(
    "faixa_ticket", classificar_ticket_pandas(col("total_amount"))
)

🏗️ Estratégias de Join Internas do Spark

┌─────────────────────────────────────────────────────────────┐
│ 1. BROADCAST HASH JOIN (BHJ)                                │
│    Condição: tabela < autoBroadcastJoinThreshold (10MB)     │
│    Custo: O(n) — sem shuffle                                │
│    Tabela pequena copiada para todos os executors            │
├─────────────────────────────────────────────────────────────┤
│ 2. SORT-MERGE JOIN (SMJ) — DEFAULT para tabelas grandes     │
│    Condição: ambas tabelas são grandes                      │
│    Custo: O(n log n) — shuffle + sort + merge               │
├─────────────────────────────────────────────────────────────┤
│ 3. SHUFFLE HASH JOIN (SHJ) — Casos específicos              │
│    Condição: uma tabela cabe na memória do executor          │
│    Custo: O(n) — shuffle + hash (sem sort)                  │
└─────────────────────────────────────────────────────────────┘

Hierarquia de preferência do Catalyst:

  1. 🥇 Broadcast Hash Join (se possível)
  2. 🥈 Sort-Merge Join (padrão para tabelas grandes)
  3. 🥉 Shuffle Hash Join (desabilitado por default)

⚠️ Data Skew — O Inimigo Silencioso

Data skew ocorre quando uma chave de join concentra quantidade desproporcional de registros em um único executor.
Distribuição IDEAL:              Distribuição com SKEW:
┌─────┐ ┌─────┐ ┌─────┐ ┌─────┐   ┌─────┐ ┌─────┐ ┌─────┐ ┌───────────┐
│250K │ │250K │ │250K │ │250K │   │100K │ │100K │ │100K │ │   700K    │
│ 10s │ │ 10s │ │ 10s │ │ 10s │   │  4s │ │  4s │ │  4s │ │   28s ⚠️ │
└─────┘ └─────┘ └─────┘ └─────┘   └─────┘ └─────┘ └─────┘ └───────────┘
 Total: 10s (ideal)               Total: 28s (gargalo!)

Soluções:

  1. Salting — Adicionar sufixo aleatório à chave de join
  2. Broadcast — Se uma das tabelas é pequena
  3. AQE (Adaptive Query Execution) — Spark 3.x otimiza automaticamente:
spark.conf.set("spark.sql.adaptive.enabled", "true")
spark.conf.set("spark.sql.adaptive.skewJoin.enabled", "true")
